For anyone

Why it exists

Three ideas do most of the work. You don't need to read code to get them.

Foundry is disposable, the vault isn't

The Foundry world is a projection you can wipe and rebuild from the vault, the git content module, and D&D Beyond. The notes you'd actually mourn live in Obsidian, under your own sync. Three restore modes back that up: a full snapshot for the undo, a --golden one that resets the instance without touching the worlds you're keeping, and --world for bringing a single world back onto an install you just rebuilt. A verify command then checks the rebuilt install against the pins and exits non-zero if it doesn't match, so “it came back” is something you can prove rather than hope. And new-world applies a captured settings template, so a rebuilt world opens configured instead of blank. This is not a claim on paper: the install was wiped and rebuilt end to end on 2026-08-21, and the six things that broke were fixed rather than written up as caveats.

No doors left open

The server runs on your machine and dials out to Cloudflare's edge. Players get a stable HTTPS URL; your router forwards nothing and exposes nothing.

An AI game master, optionally

Claude Code authors NPCs, quests and scenes as code compiled into a compendium module, and can run the live session — dice, tokens, scenes — over the foundry-mcp bridge.

For engineers

The moving parts

Each is a self-contained piece. Together they turn a folder of markdown notes into a running virtual tabletop.

Foundry containercompose.yml
The published felddy/foundryvtt-docker image — this fork builds no image of its own. Worlds and modules bind-mount from FOUNDRY_DATA_PATH; locally it answers on :30000.
Golden basefoundry-base.json
The pinned system and 24 core modules a rebuilt install needs — captured from a live world, never guessed at. provision installs them and fails if a URL served something other than the pin, verify is the gate, and new-world opens a world already configured from a captured settings template. A monthly workflow runs update --dry-run and opens a PR when pins move — it never merges one, because a locked pin going stale and a floating pin drifting are two ways to lose the same thing.
Cloudflare Tunnelcompose.cloudflare.yml
An optional overlay: cloudflared dials out to Cloudflare's edge, so remote players get HTTPS with zero inbound ports and no port forwarding.
Obsidian vaultDND_VAULT_PATH
The DM's system-agnostic source of truth, bind-mounted into Foundry (file picker sees its art and handouts) and into the devcontainer. A content-free starter ships at examples/vault-skeleton/.
Content pipelinescripts/content/
Vault notes compile into a per-game compendium module: statblocks from SRD fences, token art through a curated resolver, an art-coverage gate, then build → sync → restart. One command: ship-game.sh.
Ambienceoutside Foundry, on purpose
There is no Playlist collection — a Foundry playlist streams from your server to every client and does nothing for a session run in person. Each scene note carries its own cue; the game's Soundtrack.md names the music bot once and renders a paste-ready cue sheet; and a GM-only macro whispers the cue as the scene loads, so the music change lands at the scene change.
Battlemap generatorscripts/maps/
One JSON spec renders a Player map, a keyed DM map, and a Foundry-ready .dd2vtt with walls, lights and doors baked in; map-to-scene.sh lands it as a compendium scene.
foundry-mcp bridge.mcp.json · scripts/setup-mcp.sh
The adambdooley/foundry-vtt-mcp two-part bridge: a Foundry module in the GM's browser plus a local MCP server, letting Claude read and drive the live world — dice requests, tokens, conditions, scenes.
Dev foundation.devcontainer/ · .github/
Devcontainer with a deny-by-default firewall, pre-commit, CI gates and a Kanban board — inherited from claude_template_repo and now detached from template sync: every file here is repo-owned.

Under the hood

How the pieces actually work

Five close-ups: the content pipeline, the art resolver behind its gate, the map generator, the rebuild path that makes the world disposable, and the sealed environment the repo is developed in.

The content pipeline

scripts/content/ · ship-game.sh
vault notes NPCs as markdown with SRD statblock fences; handouts as image embeds. The note is the master copy — Foundry JSON is a projection of it.
▼
compile-game.mjs Compiles every statblock fence against the cached SRD base creature — proficiency math, divergence reports — and every handout embed, incrementally.
▼
art-coverage.mjs --strict Classifies every art slot — actor portrait and token, scene backgrounds, journal image pages — and fails the ship if any named NPC would wear a blank silhouette.
▼
build.mjs Validates each source file and every @UUID cross-link, assigns deterministic IDs, and packs LevelDB compendia plus module.json into content/dist/.
▼
sync → restart Copies the module into Foundry's data dir and restarts the container — Foundry opens LevelDB packs at start, so a restart is not optional. Import with Keep Document IDs ticked.

ship-game.sh <game-dir> runs the whole chain in one command. Games are one module each, scaffolded by new-game.sh, with sources living beside the game's vault notes — this repo is the pipeline, never the content.

Token art — the resolver chain

art-resolve.mjs · content/reference/art-map.json
image: line in the note Always wins. Vault-relative, so Obsidian's statblock plugin and Foundry render the same file.
The SRD base creature's real token Genuinely that creature's art, where the system pack ships any — measured, it mostly does not.
The curated icon map Hand-checked byName matches first, then — for mooks only — one byType silhouette per creature type. Curated, never fuzzy: fuzzy matching once paired Adult Gold Dragon with a gold bar.
Nothing — deliberately A named NPC with no art resolves to the placeholder and a warning, and the strict gate stops the ship. The gap stays visible instead of hiding behind a generic outline.

The standard fix for a stopped ship: Claude draws the token — a hand-written flat-vector SVG from the note's Appearance section, saved under the game's Assets/Tokens/ and stamped back into the note (art-stamp.mjs) so Obsidian shows it too. An optional raster tier for www.dnd5eapi.co's SRD monster PNGs is measured (334 of 334 carry images) but ships disabled until someone wants mooks in photoreal art instead of the curated icons.

Wiping the install — and getting it back

foundry-base.json · scripts/content/foundry-base.mjs
Durable — survives a wipe
vault · git · pins
  • Every note, statblock and map in the Obsidian vault, under your own sync
  • Each game's compendium module — rebuilt from those notes by pull-games
  • The pinned system and module set, and a captured world settings template
  • A full snapshot of the data dir, taken between sessions
none of it lives only inside Foundry
Transient — dies with the world
expected losses
  • Token positions, fog, the combat tracker, the active scene
  • World-scoped compendium packs (world.ddb-*) — hence a D&D Beyond re-import
  • The D&D Beyond session cookie — redacted on capture, deliberately: a template must not carry credentials out of a world
  • Anything ever typed straight into Foundry and nowhere else
the list is short on purpose
step zero · refresh the install URL Foundry's download link is presigned and expires. It is the one step that cannot be done from inside a broken install, and skipping it turns the rebuild into a 403 at the worst possible moment.
▼
snapshot The full data dir, worlds included — the undo path. It keeps the previous backup as .backup.1 and refuses to mirror an install that has lost worlds over a backup that still has them. Separate from --golden, which is the clean slate you restore onto a sick instance without touching the worlds you are keeping.
▼
provision Installs the pinned system and every core module into a bare data dir, then compares what the URL actually served against the pin and exits non-zero on drift. Roughly a minute.
▼
new-world Creates a world and applies the captured settings template, so it opens configured — module toggles, scene defaults, house rules — instead of blank.
▼
pull-games Rebuilds each game's compendium module from the vault, through the same art gate as a normal ship. Required even when a world was restored from a snapshot — the world holds documents, not the module they came from.
▼
verify The gate. Checks the rebuilt install against every pin, and the world against the template, and exits non-zero if it does not match — so “it came back” is proved rather than eyeballed.

This was run for real, not just written down: on 2026-08-21 the install was wiped and rebuilt end to end — about an hour the first time, 15–30 minutes clean, most of it Foundry downloading. It surfaced six defects nothing short of a real wipe would have found: a settings template that named the dead world's packs, seven modules unpacked one directory too deep where Foundry could not see them, and nine of twenty-five pins quietly installing whatever /releases/latest/ served that day. The lesson is in the manifest now — a pinned version is a record, not a constraint; the URL decides — and drift is a failing exit code rather than a line of output nobody reads.

The loop

From idea to game night

One game, one module, one command to ship. The order is the point — the gate sits before anything reaches Foundry.

Scaffold

new-game.sh lays out notes + module sources together.

Author

Write the notes; statblocks are SRD fences, not transcriptions.

Compile

Fences become actors; handout embeds become image journals.

Gate

Art coverage --strict: no blank tokens, proven.

Ship

Build → sync → restart Foundry; import with Keep Document IDs.

Play

Live session over MCP — dice requests, tokens, scenes, conditions.
